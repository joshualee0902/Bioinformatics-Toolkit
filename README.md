# Genomic Sequence Modeling: Coding Region Prediction with LSTMs

Can a bidirectional LSTM tell protein-coding DNA from non-coding DNA better than
hand-engineered features, and does it learn the 3-base codon rhythm of coding DNA?

This repository started as a small Tkinter DNA toolkit (now in [`legacy/`](legacy/)).
Its sequence functions were refactored into `biotoolkit/sequence.py` and now serve
as the feature-engineering layer for a reproducible ML pipeline: real genomic data,
leakage-controlled splits, strong baselines, multi-seed experiments, saliency
analysis, and a small inference API.

Every number and figure below is generated by code in this repo. The tables are
rendered from SQL queries over the experiment database by `make report`, not typed
by hand.

## Quick start

```bash
python3.11 -m venv .venv && source .venv/bin/activate
make install          # pip install -e ".[dev]"
make all              # data -> features -> baselines -> train -> evaluate -> report
make serve            # API on http://localhost:8000
```

## Problem

Binary classification of 200 bp human DNA windows:

- **label 1, coding**: taken from protein-coding sequence
- **label 0, intergenic**: taken from between genes

Coding DNA is read three bases at a time (codons), so it carries a period-3 statistical
signal, and in-frame stop codons are rare. Hand-engineered features (k-mers, codon
usage, stop-codon density) capture these explicitly. The question is whether a
sequence model can learn them from raw one-hot DNA, and whether its learned
features show the period-3 signal.

## Dataset and preprocessing

Source: `demo_coding_vs_intergenomic_seqs` (version 0) from the open-source
[genomic-benchmarks](https://github.com/ML-Bioinfo-CEITEC/genomic_benchmarks) package.
It has 100,000 human sequences, all 200 bp: 75,000 train and 25,000 test, with
balanced classes. The package stores one sequence per `.txt` file (not FASTA), so
the package's own downloader is used. Biopython parses FASTA input in the CLI.

Pipeline (`biotoolkit/data.py`, settings in `configs/data.yaml`):

1. Uppercase every sequence; drop any containing characters other than A, C, G, T, N.
2. **N rule:** keep a sequence only if at most 5% of its bases are N. Kept N bases become
   all-zero one-hot rows and are skipped when counting k-mers. (This dataset has no N
   bases, but the rule is enforced and logged.)
3. Keep lengths in 150 to 250 bp.
4. **Leakage control.** Each sequence is reduced to a canonical form,
   `min(sequence, reverse_complement)`, so a sequence and its reverse complement
   count as the same sequence.
   - The official test set is never modified.
   - Training sequences that also appear in test are removed.
   - Sequences that appear in train with both labels are removed.
   - Remaining duplicates within train are collapsed to one copy.
5. Carve a stratified 10% validation split from train (seed 42).

## Methods

**Storage.** SQLAlchemy models in `biotoolkit/db.py`:

| Table | Contents |
|---|---|
| `sequences` | Every sequence |
| `features` | Each sequence's row in the on-disk feature matrices |
| `experiments` | One row per run: config JSON, seed, git commit, timestamp |
| `metrics` | Per-split metrics, plus per-epoch learning curves |
| `pipeline_log` | Row counts at each data-pipeline step |

Storage is SQLite by default. For MySQL 8, see [Using MySQL](#using-mysql).

**Features** (`biotoolkit/features.py`):

- Normalized k-mer frequencies for k = 3, 4, 5, 6 (sparse).
- Toolkit features built with the original toolkit functions:
  - GC content, and the variance of GC across 20 bp windows
  - codon usage (64 frequencies) in each of the three forward frames
  - longest ORF (ATG to stop) and longest stop-free stretch across all six frames
  - stop-codon density in each of the six frames

**Baselines** (`biotoolkit/models/baselines.py`):

| Experiment | Model |
|---|---|
| `majority` | Always predicts the majority class |
| `gc_lr` | Logistic regression on GC content alone |
| `kmer_lr` | Logistic regression on k-mers (k = 3 to 6) |
| `gbt` | LightGBM on k-mers plus toolkit features, early stopping on validation |

**Sequence models** (`biotoolkit/models/`):

- Input: one-hot DNA (A, C, G, T; N = all zeros).
- `lstm`: 1-layer bidirectional LSTM, hidden size 64, mean+max pooling over positions,
  then a linear head.
- `cnn`: three conv blocks (kernel 9, 64 channels) with global mean+max pooling.
- `cnn_lstm`: one conv block feeding a BiLSTM.

Training (`biotoolkit/models/neural.py`):

- AdamW (lr 2e-3, weight decay 0.01), batch size 256, gradient clipping at 1.0.
- Up to 10 epochs, early stopping on validation AUROC (patience 2); the best epoch is restored.
- All hyperparameters are in `configs/*.yaml`.

**Evaluation.**

- Metrics: AUROC (primary), AUPRC, accuracy, and F1 at a 0.5 threshold, on validation and test.
- Every experiment runs with seeds 0, 1, 2; tables report mean ± sample std.
- Test AUROC gets a 95% percentile bootstrap CI (1,000 resamples).

**Ablations** (`configs/ablations/`, plus `configs/baselines/kmer_lr_k*.yaml`):

- Sequence length: the first 50, 100, or 200 bp.
- Reverse-complement augmentation on or off.
- LSTM depth (1 or 2 layers) × hidden size (32 or 64).
- k-mer size for the logistic regression.

**Interpretability** (`biotoolkit/interpret.py`):

1. Compute input × gradient saliency for 2,000 random test sequences, using the best
   seed of the LSTM and of the CNN.
2. For each saliency map, compute the Fourier power spectrum.
3. Define the **period-3 score** as the power at frequency 1/3 divided by the median
   power at all other frequencies. A score of 1 means no peak.
4. Test significance against a null that shuffles positions within each saliency map
   (200 permutations).
5. Separately, list the most important baseline features: logistic-regression
   coefficients and LightGBM gain.

## Limitations

- **Short windows.** At 200 bp, few windows contain a complete ATG-to-stop ORF, so
  ORF-length features are weak. Real gene finding works on much longer contexts.
- **Easy negatives.** Intergenic DNA differs from coding DNA in composition (GC
  content alone gets far above chance), so the benchmark is easier than separating
  coding sequence from introns or UTRs.
- **Seed variance only.** Mean ± std covers training randomness only. The data split
  is fixed, and the bootstrap CI covers test-set sampling.
- **MPS non-determinism.** On Apple-silicon GPUs (MPS), LSTM training is not
  bit-for-bit deterministic even with fixed seeds. Re-runs agree within seed variance,
  not exactly. CPU runs are deterministic but take about 3× longer.
- **Little tuning.** Hyperparameters were set once, a priori. Nothing was tuned on
  the test set, and validation was used only for early stopping and choosing the best
  seed to serve.
- **No pretrained models.** Transformers and pretrained DNA language models were out of
  scope and are natural future work.

## Reproducing everything

```bash
make all          # full pipeline from scratch
```

| Command | What it does | Approx. time (Apple M-series, MPS) |
|---|---|---|
| `make data` | Download, validate, dedup, split, load into the DB | 1–2 min |
| `make baselines` | Build features, train 9 baseline configs × 3 seeds | 7 min |
| `make train` | Train 12 neural configs × 3 seeds, export best LSTM | see note below |
| `make evaluate` | Results tables and plots from the DB into `reports/` | < 1 min |
| `make report` | Saliency and periodicity analysis, refresh README sections | 1 min |
| `make test` / `make lint` | pytest (includes 1-epoch smoke tests) / ruff | < 1 min |

The `make train` time is reported in [Compute](#compute).

The default seeds are 0, 1, 2. Override them with `make train SEEDS="0 1 2 3 4"`.
Baselines and neural models run in separate processes on purpose: LightGBM and
PyTorch ship different OpenMP runtimes that crash in one process on macOS.

### Using MySQL

```bash
make mysql                     # docker compose up -d mysql (MySQL 8)
export BIOTK_DB_URL=mysql+pymysql://biotk:biotk@127.0.0.1:3306/biotoolkit
make all
```

### Serving

```bash
make serve                     # uvicorn on port 8000, model = artifacts/models/lstm_best.pt
curl -s localhost:8000/health
curl -s -X POST localhost:8000/predict -H 'content-type: application/json' \
     -d '{"sequences": ["ATGGCGTTGCTGCTGGCCGCGCTG"]}'

biotoolkit predict --model artifacts/models/lstm_best.pt --fasta examples/sample.fasta

make docker-build && docker run -p 8000:8000 biotoolkit
```

Behavior:

- Sequences must be A, C, G, T, or N (case-insensitive). Anything else returns HTTP 422
  with the index of the bad sequence.
- Inputs longer than the model's training length (200 bp) are truncated; shorter
  inputs are padded with N.
- The Docker image copies `artifacts/models/lstm_best.pt`, so run `make train` first.

## Repository layout

```
biotoolkit/
  sequence.py      refactored toolkit functions (typed, tested)
  data.py          download, validation, dedup, splits -> DB
  db.py            SQLAlchemy models and helpers
  features.py      k-mer and toolkit features
  models/          baselines.py, lstm.py, cnn.py, neural.py (training loop)
  train.py         config-driven training entry point
  evaluate.py      metrics, bootstrap CIs, SQL results table, plots
  interpret.py     saliency and periodicity analysis
  serve.py         FastAPI app
  cli.py           `biotoolkit predict` and `biotoolkit export-best`
configs/           one YAML per experiment
reports/           generated tables and figures
tests/             pytest suite (sequence functions, features, dedup, models, API)
legacy/            original Tkinter app
```

## Legacy Tkinter app

The original GUI (`legacy/project.py`) still runs. Its `DNAToolkit.py` and
`structures.py` are now thin shims over `biotoolkit/sequence.py`.

```bash
cd legacy && python project.py
```

Changes from the original:

- Fixed edge cases: empty-input GC content, window size 0, `N` in translation.
- `codon_usage` raises an error on invalid input instead of silently returning `{}`.
- Fixed typos: `protenis_from_rf` is now `proteins_from_rf`; `final_reoprt.txt` is
